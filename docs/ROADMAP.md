## 3. Phase 1 — 高质量阅读 MVP

> 状态（2026-11-10）：Phase 1/3/5 完成；Phase 2 全书 34 章/219 节覆盖完成（558 先修/446 相关/0 环）；T18 优先级校准进行中，P0 154/219（70.3%）；Phase 6 开源准备等待用户明确确认；T14 公式收藏为 backlog。

### 3.1 目标

先让教材“比 PDF 更好读、更好找、更容易判断该不该学”。不做练习状态、路径、复习、AI。

### 3.2 范围

**内容：**

- 34 章目录全部呈现（结构完整）。
- 仅 4 个试点章开放阅读：C01、C08、C11、C33。
- 其余章在目录中显示“内容接入中”，不可点击；不伪造内容。
- 4 章完成 D/P 标注（每节），经 DSH 复核。

**功能：**

- 首页：继续学习、今日面板（静态推荐可先基于试点章）、三条路径介绍（占位）、全书地图。
- 目录：8 篇 34 章、节级展开、D/P/时长、状态点、筛选（P0/P1、D 级、未学）。
- 阅读页：三栏、章首、节、环境、公式、习题与解析折叠、右栏元数据。
- 阅读记录：最近位置、节级进度、滚动位置、继续阅读。
- 主题：浅色/深色/跟随系统。
- 阅读偏好：字号 4 档、宽度 3 档、专注模式、证明默认折叠。
- 复制：章节链接、环境链接、公式 LaTeX。
- 响应式：1440/1280/1024/390 四档。
- 基础键盘：`[` `]`、`f`、`t`、`?`。
- 练习：章末习题渲染 + 解析折叠；状态按钮暂不开放（Phase 3）。

**工程：**

- 内容编译：Markdown → HTML + KaTeX 预渲染；34 章数据全部生成，但仅 4 章开放。
- 校验：文本覆盖率、公式、锚点、习题解析匹配。
- 前端：Vite + React + TS、设计系统 CSS、路由、状态存储。
- 测试：解析/渲染 golden、存储、阅读页集成。

### 3.3 任务拆解

### 3.4 验收标准（硬门槛）

1. **内容**：4 章正文覆盖率 100%；公式 KaTeX 错误 0；习题解析匹配 100%；环境/公式锚点全部可用。
2. **阅读**：正文列宽 680–720px；行高 1.9；首屏至少 18 行正文；长公式不撑破布局。
3. **导航**：首页 → 任意试点节 ≤3 次点击；目录当前位置高亮；上一节/下一节可用；深链 `#c11-thm-11.3` 定位准确。
4. **标注**：4 章每节显示 D/P/时长/先修/相关/理由入口；未标注章不显示假标签。
5. **状态**：阅读位置刷新后恢复；滚动不自动改“已学习”；状态菜单可手动切换并持久化。
6. **主题**：浅/深色切换无白闪；字号/宽度/专注模式持久化。
7. **响应式**：390px 无横向滚动；移动端可完成“目录→阅读→标记→下一节”。
8. **视觉**：对照 `DESIGN_SYSTEM.md` 第 15 节逐条通过；无禁止项。
9. **性能**：首屏 JS ≤250KB gzip；阅读页正文 ≤1.5s 出现；无长任务 >100ms。
10. **测试**：`npm run content:validate` 0 error；`npm --prefix web run test` 通过；`npm --prefix web run build` 成功。

### 5.1 目标

让用户能够“定路线 → 学 → 练 → 记 → 复习 → 看进度”，并可靠保存。

### 5.2 范围

- 学习状态五态；状态菜单；活动日志。
- 进度面板：总覆盖、分篇、P0/P1、练习、错题、复习、最近活动。
- 章内练习：展开解析、自评做对/做错、收藏、错题本、重做。
- 笔记：KP 级 Markdown、自动保存、导出。
- 复习：Leitner 5 盒（1/3/7/21/45 天）；到期队列；升降盒；可解释规则。
- 数据：导出/导入 JSON、备份、清空、schema 迁移。

### 5.3 任务拆解

7. 导出 → 清空 → 导入 → 状态/笔记/错题/复习完全恢复。

## 6. Phase 4 — 学习体验增强

### 6.1 目标

在不伤害阅读与性能的前提下，增加真正提升理解的交互。

### 6.2 范围（按价值排序，可裁剪）

1. **分步推导**：10–15 个关键证明/推导；逐步展开 + 每步解释；原文仍可完整阅读。
2. **可视化**：正态分布、CLT、Bayes、矩阵变换、特征值、梯度下降、有效前沿、布朗运动；每个组件标注假设、参数、对应公式。
3. **搜索增强**：同义词、相关知识点推荐、搜索历史。
4. **学习建议**：基于路径/状态/复习的规则式建议，可解释。
5. **公式收藏**：从正文收藏公式，进入复习/笔记。
6. **习题辅助**：分步提示（仅人工编写，不自动生成）。

### 6.3 验收标准

1. 每个分步推导与原文数学一致；不改变结论/条件；有“查看完整原文”入口。
2. 每个可视化：模型正确、参数有标签、图表与公式一致；移动端可操作；无 JS 时显示静态说明。
3. 可视化按需加载，不影响阅读页首屏；性能预算不退化。
4. 学习建议可解释，不调用外部 AI；用户可忽略。
5. 至少 3 个可视化与 5 个分步推导通过数学正确性复核。

### 6.4 出口

- 增强功能逐项验收；未达标的砍掉，不带病上线。

## 9. 任务执行规范（对 AGY）

每个任务必须：

1. 先读任务书与相关文档，确认范围与不做项。
2. 只改任务书允许的文件；不修改 `src/` 教材正文，除非任务明确授权。
3. 实际运行命令，报告退出码与关键输出；不伪造测试通过。
4. 提交可运行的代码；不能只给片段。
5. 报告：新增/修改文件、运行命令、结果、未解决问题、下一步建议。
6. 不使用“已完成”代替验收证据；截图/测试/日志至少提供一种。
7. 发现任务书与源文件冲突时，先按任务书实现并记录证据，不静默改规则。
8. 不擅自扩大范围（不加未要求的功能、不改设计系统、不引新依赖）。

DSH 每个任务验收：

1. 读代码与 diff，不只看报告。
2. 运行构建/测试。
3. 打开页面实际检查（桌面 + 移动）。
4. 对照验收清单逐条判定。
5. 记录问题与修复任务；未达标不进入下一阶段。

## 11. 决策记录（Phase 0）

| 决策 | 结论 | 理由 |
|---|---|---|
| 技术栈 | Vite + React + TS | 静态、轻、够用；内容预渲染解决首屏 |
| 后端 | 无 | 单用户、本地数据、隐私、部署简单 |
| 知识点粒度 | 一级节 | 教学单元与复习粒度匹配；避免 1,300 个状态点 |
