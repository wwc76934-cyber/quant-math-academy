# 内容模型与标注规范

- 版本：v1.0（Phase 0 定稿）
- 状态：Phase 1 内容编译与标注的唯一依据
- 关联：`../architecture/TECH_ARCHITECTURE.md`、`../product/PRD.md`、`../design/DESIGN_SYSTEM.md`

---

## 1. 总原则

1. **`src/` 是唯一内容权威。** 网站、搜索、练习、标注都引用源文件切片；不得在网站侧维护第二份正文。
2. **转换只做结构化，不做改写。** 解析器可以切分、编号、包装 HTML，但不得压缩、润色、修正或“优化”教材原文。
3. **稳定 ID。** 章节、节、环境、公式、习题都有稳定 ID；ID 一旦发布不随编号调整而改变（必要时保留别名）。
4. **标注可追溯。** 每个难度/必要性判断都必须有理由、来源节、复核状态；机器生成只作为草稿，不能直接标为已复核。
5. **内容与标注分离。** 正文文件不写 D/P 标签；标注在 `content/metadata/` 中维护，可独立修订。
6. **失败显式。** 解析或校验不通过时构建失败并列出位置，不静默跳过、不用默认值掩盖缺失。

### 2.2 ID 规则

| 实体 | 规则 | 示例 |
|---|---|---|
| 章 | `c` + 两位章号 | `c01`、`c11`、`c34` |
| 一级节（知识点 KP） | `c{章号}-s{节序号}` | `c11-s4` |
| 二级节 | `c{章号}-s{节序号}-{子序号}` | `c11-s4-1` |
| 定义 | `c{章号}-def-{章内编号}` | `c11-def-11.1` |
| 定理 | `c{章号}-thm-{章内编号}` | `c11-thm-11.3` |
| 引理 | `c{章号}-lem-{章内编号}` | `c25-lem-25.1` |
| 命题 | `c{章号}-prop-{章内编号}` | `c11-prop-11.2` |
| 推论 | `c{章号}-cor-{章内编号}` | `c11-cor-11.18` |
| 例题 | `c{章号}-ex-{例题编号}`（编号含小数点） | `c11-ex-11.1` |
| 注记 | `c{章号}-note-{章内编号}` | `c01-note-1.3` |
| 公式 | `c{章号}-eq-{tag}` | `c11-eq-11.2` |
| 习题 | `c{章号}-ex-{题号}`（题号为整数） | `c11-ex-1` |
| 解析 | `c{章号}-sol-{题号}` | `c11-sol-1` |
| 学习路径 | `path-{a|b|c}` | `path-a` |
| 路径阶段 | `path-{mode}-w{周号}` | `path-a-w3` |

注意：例题与习题共用 `ex` 前缀，但例题编号含小数点、习题编号为整数。**代码必须按实体类型字段判断，不能仅凭前缀正则区分。** 这是 v1 冻结约定；若未来迁移为 `exm`/`q`，必须提供 ID 别名表与数据迁移。

### 2.3 节标题解析

- 一级节必须匹配 `^## (\d+)\.(\d+)\s+(.+)$`，章号必须与文件章号一致。
- 二级节必须匹配 `^### (\d+)\.(\d+)\.(\d+)\s+(.+)$`。
- `## 本章小结`、`## 习题` 是保留节，不生成 KP ID。
- 标题中的行内公式保留 LaTeX 原文；网页渲染时转 KaTeX。
- 章标题首行格式：`# 第N章　标题`，分隔符为全角空格 U+3000；解析时允许一个或多个空白。

## 3. 环境与正文切片

### 3.1 环境类型

| 类型 | 中文标记 | 字段 `kind` | 是否编号 | 可附证明 | 可附解 |
|---|---|---|---|---|---|
| 定义 | `**定义 11.1（…）**` | `definition` | 是 | 否 | 否 |
| 定理 | `**定理 11.3（…）**` | `theorem` | 是 | 是 | 否 |
| 引理 | `**引理 25.1（…）**` | `lemma` | 是 | 是 | 否 |
| 命题 | `**命题 11.2（…）**` | `proposition` | 是 | 是 | 否 |
| 推论 | `**推论 11.18（…）**` | `corollary` | 是 | 是 | 否 |
| 例题 | `**例 11.1**` | `example` | 是（独立序列） | 否 | 是 |
| 注记 | `**注记 11.3**` | `note` | 是 | 否 | 否 |
| 证明 | `**证明**` | 附属于定理类 | 否 | — | — |
| 解 | `**解**` | 附属于例题 | 否 | — | — |

- 定义/定理/引理/命题/推论共用章内连续序号；例题独立编号；注记按出现顺序编号（若教材有）。
- 证明以单独一行 `**证明**` 开始，以单独一行 `□` 结束；`□` 也可写作 `∎`，解析器需记录变体。
- 解以单独一行 `**解**` 开始，到下一个环境标题、节标题或文件末尾结束。
- 环境正文必须保留原始 Markdown（含标题行），供渲染器与审计使用。

### 3.2 公式

- 独立公式：`$$ ... $$`，可跨行；`\tag{x.n}` 可在公式末尾同一行或单独一行。
- 行内公式：`$...$`；不得跨段落。
- 公式 ID 由 tag 生成；无 tag 的独立公式保留在 `equations` 中但 `id: null`，不参与锚点。
- 公式编号必须章内连续；`\tag` 值与章号一致。
- 渲染前剥离 `\tag`，由渲染器输出编号；`data-latex` 保留完整原文（含 tag）。
- 公式复制提供 LaTeX 原文；不自动改写 `\operatorname`、`\boldsymbol` 等写法。

### 3.3 表格

- 仅当“一行以 `|` 开头并以 `|` 结尾，且下一行是 `| --- |` 形式的分隔行”时判定为表格。
- 表格单元格内的行内公式必须保留并渲染；单元格内的 `|` 需转义 `\|`，解析器要能识别。
- 首版不支持合并单元格、复杂表头；若教材出现，记录警告并按普通表格渲染。

### 3.4 习题与解析

- 习题区从 `## 习题` 开始；题号行 `^(\d+)\.\s`。
- 题内可有多段、公式、列表、小问；小问编号 `(1)`、`1)`、`①` 不切断题目。
- 解析文件标题 `## 1.`、`## 2.`；题号必须与习题一一对应。
- 解析与习题在数据中通过 `number` 关联，不依赖文件顺序。
- 解析中的“略/显然/同前”若出现，记录质量警告（教材规范禁止）。

## 4. 章节数据 schema（网站消费）

完整定义见 `TECH_ARCHITECTURE.md` 第 4 节与 T01 任务书。关键约束：

- `book.json` 只含目录、统计、路径入口；不含全文。
- `chapters/cXX.json` 含导言、节、环境、公式、习题、解析；正文以 HTML 或 Markdown 切片存在，二者只能选一种作为渲染输入。
- 每个节必须含 `id`、`number`、`title`、`anchor`、`environmentIds`、`exerciseIds`。
- 每个环境必须含 `id`、`kind`、`number`、`title`、`sectionId`、`anchor`。
- 每个习题必须含 `id`、`number`、`sectionId`、`solutionMarkdown`（允许为空但需警告）。
- 统计字段必须与数组长度一致；构建校验会复核。

### 4.1 渲染后的 HTML 约定

- 节容器：`<section id="c11-s4" data-section-id="c11-s4">`。
- 环境容器：`<section class="env env--theorem" id="c11-thm-11.3" data-env-kind="theorem" data-env-number="11.3">`。
- 公式容器：`<div class="equation" id="c11-eq-11.2" data-latex="...">`，编号 `<span class="equation__number">(11.2)</span>`。
- 习题容器：`<article class="exercise" id="c11-ex-1" data-exercise-number="1">`。
- 所有锚点必须唯一；重复 ID 构建失败。
- 正文 HTML 由构建期生成，不使用运行时 Markdown 解析；客户端只注入并绑定事件。

### 5.3 元数据状态

- `pending`：该节尚未标注。UI 显示“标注完善中”，不显示 D/P。
- `draft`：AGY 起草，含 rationale，`reviewed:false`。可用于内部预览，不对外展示为可信标注。
- `reviewed`：DSH 复核，`reviewed:true`。对外展示。
- `revised`：复核后因教材或用户反馈调整；保留 `changeLog`（可选）。

Phase 1 只允许 `reviewed` 的节在正式 UI 显示 D/P；`draft` 可在开发模式显示并带“草稿”水印。

## 6. 难度分级 D1–D5（标注手册）

### 6.1 定义与判定

| 等级 | 名称 | 判定标准 | 典型特征 |
|---|---|---|---|
| D1 | 基础 | 定义复述、单步计算、直接代入；不需要多步推导 | 概念、记号、简单性质 |
| D2 | 基础进阶 | 2–3 步推导；需要选择一个标准工具；代数变形可控 | 方差性质、Bayes 公式、矩阵运算 |
| D3 | 核心进阶 | 多步证明或综合计算；需要条件辨析；连接两个以上概念 | 谱定理、概率不等式、MLE、CLT 证明 |
| D4 | 高级 | 较长证明或较高抽象度；需要测度论/泛函/随机分析成熟度 | 鞅收敛、Itô 积分构造、Girsanov |
| D5 | 挑战 | 复杂证明链、多个高级工具、研究级抽象；完整掌握需显著时间 | Doob 分解细节、Feynman–Kac 验证、EVT 证明 |

判定时问三个问题：

1. 读者能否只靠本节定义与前一节结论完成？能 → D1/D2。
2. 是否需要主动选择定理、构造辅助对象、处理一致收敛/可积性等条件？是 → D3/D4。
3. 证明是否跨多页、依赖多个高级分支，且首次阅读难以独立补全？是 → D5。

**不以篇幅长短直接定级。** 一个短但极抽象的定义可以是 D4；一个长但机械的计算可以是 D2。

### 6.2 校准示例

| 节 | D | 理由 |
|---|---|---|
| 1.1 命题、逻辑联结词与量词 | D2 | 概念不难，但量词否定与多层量词顺序需要精确训练 |
| 1.4 实数完备性及其基本推论 | D4 | 确界、单调有界、区间套相互推导，抽象度明显上升 |
| 8.3 奇异值分解 | D3 | 需要内积、特征值、矩阵范数综合；证明与计算并重 |
| 8.4 主成分分析 | D3 | 在 SVD 之上做统计解释，需理解方差最大化与投影 |
| 11.4 概率不等式 | D3 | 多个不等式、条件与紧性辨析；证明长度中等 |
| 25.4 停时与可选停时定理 | D5 | 需要一致可积、停时截断、反例构造，完整证明链长 |
| 33.5 Black–Scholes 模型与公式 | D4 | 需 Itô 公式、PDE、风险中性定价与正态积分综合 |
| 34.1 收益序列与绩效指标 | D2 | 定义与计算为主，夏普标准误的推导略高但整体可控 |

### 6.3 常见错误

- 把“考试常考”误当难度高：高频计算题可能只是 D2。
- 把“篇幅长”误当难度高：长节可能包含多个 D2 主题。
- 把“证明没读懂”直接标 D5：先判断是前置知识缺失还是本节本身抽象。
- 全章统一一个等级：必须逐节判断。

## 7. 学习必要性 P0–P3（标注手册）

### 7.1 定义

| 等级 | 名称 | 判定标准 | 学习建议 |
|---|---|---|---|
| P0 | 必须掌握 | 量化实习笔试/面试高频；或后续多个核心章节的必要基础；应能独立计算/证明/解释 | 首轮必学，配练习，进入复习 |
| P1 | 重点掌握 | 量化研究/建模重要；常作为区分度知识；依赖 P0 基础 | 核心路径学习，掌握主要结论与用法 |
| P2 | 建议学习 | 有较高拓展价值，面向特定方向（衍生品、风险、时序等） | 按方向选学，理解结论即可 |
| P3 | 选修拓展 | 高级理论、长证明或细分领域；对多数实习岗位非必需 | 兴趣/研究需要时学习，可跳过细节 |

### 7.2 判定维度

1. **考核频率**：量化实习笔试/面试是否常直接考（计算、证明、概念辨析）。
2. **下游依赖**：后续有多少核心节依赖它；是否为多条主线的必经节点。
3. **工作使用**：量化研究日常是否直接用（估计、检验、回归、优化、回测、风险）。
4. **替代成本**：不会它是否可以用工具/查表绕过；绕过是否影响理解。
5. **方向性**：是否只对特定岗位（如衍生品定价、高频）重要。

判定规则：

- P0：至少满足“高频考核”或“3 个以上核心下游依赖”之一，且不是纯高级理论。
- P1：满足“研究常用”或“2 个以上下游依赖”，但可通过工具辅助。
- P2：有明确应用场景，但非核心路径；或需要较多前置。
- P3：长证明/研究级/细分方向；跳过不影响主线。

### 7.3 校准示例

| 节 | P | 理由 |
|---|---|---|
| 11.4 概率不等式 | P0 | 面试高频；尾部界、样本复杂度、回测误差都依赖 |
| 8.3 奇异值分解 | P0 | PCA、最小二乘、伪逆、降维的共同基础；高频 |
| 8.4 主成分分析 | P1 | 重要但可由 SVD 工具完成；研究方向偏 P0 |
| 20.2 正态总体下的经典区间 | P0 | 统计推断基础；t/z/χ² 区间高频 |
| 25.4 停时与可选停时定理 | P2 | 美式期权/最优停止需要；多数实习不直接考完整证明 |
| 29.3 GARCH(1,1) | P1 | 波动率方向核心；非波动率岗位可后置 |
| 33.5 Black–Scholes 模型与公式 | P1 | 衍生品方向 P0；其他方向理解结论即可 |
| 34.1 收益序列与绩效指标 | P0 | 夏普、回撤、年化是量化研究通用语言 |

### 7.4 常见错误

- 把“难”当“重要”：D5 的证明可能只是 P2/P3。
- 把“应用节”一律标 P3：量化应用节常含 P0 指标与方法。
- 全章一个 P：必须逐节判断，章内差异可能很大。
- 用关键词自动打标：如出现“定理”就标 P0，出现“注记”就标 P3，均禁止。
- 伪造“公司真题”：不得声称某题来自某公司；只写“高频考点/常见题型”。

## 8. 学习时间估算

- 基准：中文数学正文 300–400 字/分钟；公式密集段按 0.6–0.8 倍速度。
- 证明：每页（约 1,200 字）额外 5–10 分钟。
- 例题：每题 5–10 分钟（含自行推导）。
- 估算后向上取整到 5 分钟，范围 20–180 分钟。
- 元数据写 `minutes`，UI 显示“约 X 分钟”；不承诺精确。

参考：

| 节类型 | 典型分钟 |
|---|---|
| 概念 + 简单性质（D1–D2） | 25–40 |
| 标准推导 + 2–3 例题（D2–D3） | 40–60 |
| 多定理证明 + 综合例题（D3–D4） | 60–90 |
| 长证明/高级理论（D5） | 90–150 |

## 9. 标签体系

标签用于检索与关联，不替代 D/P。建议 2–6 个，优先使用受控词表：

**数学分支**：分析、线性代数、概率论、数理统计、优化、随机过程、随机分析、时间序列、数值计算、金融数学、组合数学。

**内容类型**：定义、定理、证明、计算、建模、反例、应用。

**量化主题**：组合优化、风险度量、衍生品定价、因子模型、回测评估、执行成本、波动率、统计推断、机器学习。

**方法/工具**：矩阵分解、特征值、凸优化、KKT、MLE、Bayes、假设检验、回归、GARCH、Kalman、Monte Carlo、Itô 积分。

规则：

- 标签不是句子；不超过 12 字。
- 不使用“重要”“难点”“必考”等评价词（这些属于 P 级与 rationale）。
- 同一节标签不重复；大小写统一。
- 新标签先加入 `content/metadata/tags.json` 再使用；未登记标签给警告。

## 10. 先修与相关知识

### 10.1 先修

- 语义：不掌握该先修，学习本节会明显受阻。
- `required`：必须；UI 在未掌握时提示“建议先补”。
- `helpful`：有帮助；UI 以较弱提示显示。
- 必须是**更早的节**（允许少量跨篇但必须已出现）；不得指向自身或未来节。若确实需要后续节（如应用章回指），放入 `related` 而非 `prerequisites`。
- 先修图必须无环；构建时做拓扑检查。

### 10.2 相关

- 语义：概念相近、可对照、可延伸，或同一应用簇。
- 0–6 个；不要求对称，但构建时对单向关系给提示，便于人工补全。
- 不制造“为了图谱好看”的弱关联；每条 related 应能在 rationale 或正文中找到依据。

### 10.3 应用场景

- 1–4 条，具体到量化工作：如“用 SVD 构建统计因子”“用 GARCH 预测 VaR”“用 Kalman 滤波估计时变 beta”。
- 不写空泛的“用于金融”。

## 12. 检索文档 schema（Phase 2）

```json
{
  "id": "c11-s4",
  "type": "section",
  "chapterId": "c11",
  "sectionId": "c11-s4",
  "title": "11.4 概率不等式",
  "text": "……纯文本，去除 Markdown 标记，保留数学术语与公式的 LaTeX 简写……",
  "tags": ["概率论", "不等式", "尾部界"],
  "priority": "P0",
  "difficulty": "D3"
}
```

- `type`：`section | definition | theorem | lemma | proposition | corollary | example | note | exercise | solution | application`。
- `text` 截断到 2,000 字；保留标题与首段，避免索引过大。
- 公式：同时保留 LaTeX 原文与去除命令后的可读文本（如 `\operatorname{Var}` → `Var`），便于搜索“方差/Var”。
- 别名：`content/search/aliases.json`，如 `{"期望":["expectation","mean","expected value"], "特征值":["eigenvalue","eigenvalues"]}`。
- 索引不包含笔记、用户输入；搜索只针对教材内容。

## 13. 校验规则

构建时 `validate-content.mjs` 必须检查：

### 13.1 结构

1. 34 章、34 解析文件；章号 1–34 无缺漏。
2. 篇归属与第 2.1 节一致。
3. 一级节编号 `x.1..x.k` 连续；二级节编号与一级节前缀一致。
4. 每个节有非空正文；`本章小结` 与 `习题` 存在。
5. 环境 ID 全局唯一；章内序号连续（定义/定理/引理/命题/推论共享序列；例题独立）。
6. 证明有归属；无归属证明记 warning；`□` 缺失记 warning。
7. 公式 tag 章内连续、无重复；`\tag` 的章号与文件一致。
8. 习题题号连续；解析题号与习题 1:1；缺解析为 error。
9. 所有锚点唯一；目录中的锚点在章节 HTML 中存在。

### 13.2 内容保真

10. **文本覆盖率**：每节源文本去除 Markdown 标记、公式、空白后，与渲染后纯文本的字符序列一致；差异必须为 0 或仅空白/标点归一化差异。
11. 公式渲染：所有行内/独立公式 KaTeX 渲染成功；失败为 error。
12. 表格：行列数与源一致；单元格文本不丢失。
13. 环境切片可在源文件中按空白归一化后逐字找到。

### 13.3 元数据

14. 试点章每节都有 `difficulty`、`priority`、`minutes`、`examFrequency`、`learningObjective`、`rationale`。
15. D/P 枚举合法；minutes 为 5 的倍数且在 20–180。
16. 先修 ID 存在、不是自身、不是未来节；先修图无环。
17. related ID 存在、不是自身；单向关系给提示。
18. keyFormulas ID 存在。
19. tags 2–6 个、长度合规、已在词表登记（未登记给 warning）。
20. `reviewed:true` 必须有 `reviewedBy` 与 `reviewedAt`。
21. 路径 A 的 KP 均为 P0/P1；路径 B 覆盖全部 KP；路径中的 ID 存在且不重复。

### 13.4 错误级别

- `error`：阻断构建，必须修复。
- `warning`：构建通过，但写入 `validation.json`，在报告中列出；不允许长期积累超过阈值（Phase 1 目标 warning ≤ 20，且逐条有说明）。

## 14. 标注工作流

### 14.1 试点（Phase 1）

1. DSH 选定 4 章：C01、C08、C11、C33。
2. AGY 逐节阅读原文，按本规范起草 `content/metadata/chapters/cXX.json`：
   - 每节填 D/P/分钟/标签/应用/先修/相关/目标/理由；
   - `reviewed:false`，`reviewedBy:null`。
3. DSH 逐节复核：
   - 抽查理由是否引用正文特征；
   - 检查 D/P 是否混淆；
   - 检查先修是否真实；
   - 修改后设 `reviewed:true`，填复核人/日期。
4. 运行校验器；全通过后 UI 才展示 D/P。
5. 记录校准结论到 `docs/audit/metadata-calibration.md`，供全书批量参考。

### 14.2 全书（Phase 2/3）

- 按篇分批：每批 2–3 章，AGY 起草 → DSH 复核 → 校验。
- 先做 P0/P1 的准确性，再补 P2/P3；D 级可先粗后细。
- 任何自动生成只作为草稿，必须逐节人工确认；不得直接把模型输出标为 reviewed。
- 建立“争议节”清单：D/P 难以判断的节，记录两种意见与最终理由。

### 14.3 修订

- 用户反馈、教材改版、路径调整都可能触发标注修订。
- 修订保留 `changeLog`：日期、字段、旧值、新值、理由。
- 不删除历史；导出时包含当前值与版本。

## 16. 内容许可与开源边界

- 教材正文版权归作者/权利人所有；代码许可证不自动覆盖内容。
- `content/metadata` 与 `content/paths` 属于项目数据，是否随代码开源由作者决定。
- 开源前必须：
  1. 确认正文、例题、习题、解析的再分发权利；
  2. 确认参考资源（Quant Engine 等）未提供受版权保护的原文；
  3. 审计字体、图片、第三方依赖许可证；
  4. 在 README 中明确“代码许可”与“内容许可”的边界；
  5. 如内容不能公开，提供 `content-sample/`（1–2 章示例）与导入说明，主仓库只含代码。
- 未经作者明确确认，不创建公开仓库、不部署公开站点。

## 17. 新增章节流程

1. 将正文放入 `src/chapters/Cxx-*.md`，解析放入 `src/solutions/Cxx-solutions.md`。
2. 更新篇归属常量 / `content/metadata/parts.json`（如新增篇）。
3. 运行 `npm run content:inventory` → 检查解析与校验。
4. 运行 `npm run content:build` → 生成章节 JSON。
5. 在 `content/metadata/chapters/cxx.json` 添加标注；先 draft，复核后 reviewed。
6. 运行 `npm run content:validate` → 0 error。
7. 在 `book.json` 目录中确认章节出现；构建前端并检查路由。
8. 更新 `docs/audit/textbook-audit.md` 统计与 `README` 章节数。
